2. The idea in 20 seconds (say this first)

"Phishing detectors are tested on public datasets and report about 99% accuracy. We found that in the most-used dataset, PhiUSIIL, every legitimate URL is written as https://www.site with nothing after it, and almost no phishing URL is. So a model can score 99% just by checking the format. Our method, the canonicalisation ladder, trains the same model three times while removing the format step by step. If accuracy falls, the dataset has a shortcut. The app shows this live."

The app has three models. All three are the same XGBoost classifier trained on the same data; they differ only in what part of the URL they see:

ModelWhat it seesAccuracy on unseen websites
A: Raw URLThe URL exactly as written99.60%
B: Cleaned URLhttps://, www. and trailing / removed83.91%
C: Name onlyOnly the website name79.66%

4. Terminal demo (more detail): run cli

Use this when teachers want to see the model working in the terminal. Make the Terminal window wide (full screen). Type a URL and press Enter; the screen shows four steps:

Step on screenWhat to say
STEP 1 What each model receives"The same URL is rewritten three ways. Model A sees it raw, Model B without https://www., Model C only the website name."
STEP 2 The 24 numbers"Each model turns its text into 24 numbers: length, dots, digits, symbols, randomness. Rows in magenta differ between models; those differences come only from the formatting."
STEP 3 Which numbers pushed the decision"For each model, the five numbers that pushed it most. Red pushes towards phishing, green towards safe. For Model A, url_len often dominates: it learned that legitimate URLs have the length of https://www.site."
STEP 4 DecisionPhishing score bar and SAFE / PHISHING for each model.
What this meansTrue label if the URL is in the dataset, and whether that website was in training or test; the one-line format rule; and whether Models A and B disagree (the shortcut).

6. Questions teachers may ask

QuestionAnswer
Where is the dataset?phishing-audit/data/raw/phiusiil/PhiUSIIL_Phishing_URL_Dataset.csv. Also shown in the Dataset & Model tab.
Where is the model?phishing-audit/models/xgb_R1.joblib, xgb_R2, xgb_R3 (Models A, B, C).
Where is the code?phishing-audit/audit/: canon.py (cleans URLs), features.py (24 features), evaluate.py (training and testing). run_audit.py runs all experiments; app.py is the web app.
Frontend and backend?Built with Streamlit (Python). The backend loads the three saved XGBoost models and computes features; the frontend is the web page it serves. run start starts both.
Why is Model A "wrong" if it is 99.6% accurate?It is accurate on this dataset only because of how the dataset was collected. On a real URL written differently (e.g. without https://www.) it fails, as the wikipedia.org example shows.
Is Model B a better phishing detector?Not the goal. The project is a diagnostic for datasets: the drop from A to B measures how much a benchmark rewards formatting.
Did the model see the test URLs?No. Test websites are completely separate from training websites (domain-disjoint split).
Why XGBoost?Strong, fast tree model widely used in phishing papers. We also used logistic regression, random forest and a character n-gram model; all show the same drop.
Can I re-run everything?Yes: .venv/bin/python run_audit.py in phishing-audit recomputes all results (a few minutes).

7. If something goes wrong

  • Page does not open: type run start again (it restarts cleanly).
  • Page looks blank or old: refresh the browser.
  • Error message: see phishing-audit/results/app.log.
